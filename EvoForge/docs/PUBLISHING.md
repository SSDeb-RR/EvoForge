# Publish this folder to GitHub manually

This folder is ready to become a new public repository named **EvoForge** (a
good repository slug is `evoforge`). No Git repository or remote is included.

## Before you publish

1. Read the repository README and choose a license appropriate for your goals.
   The package deliberately does not invent a legal license on your behalf.
2. Confirm that `harnesses/evoforge-rsi/evolution/` contains only the empty
   skeleton and no real conversation evidence.
3. Review `docs/INSTALL.md` on the platforms you intend to support.
4. Optionally replace the generic repository links once your GitHub URL exists.

## GitHub web workflow

1. Create a new GitHub repository named `evoforge` (or your preferred name).
2. Do not initialize it with conflicting starter files if you plan to upload
   this folder as the initial contents.
3. Upload the contents *inside* this `EvoForge` folder, preserving its folder
   structure.
4. Review the uploaded file list for accidental local evidence or credentials.
5. Commit through GitHub's web interface and publish the repository.
6. Add the repository URL near the top of `README.md` if you want a canonical
   clone/download link.

No generated `evolution/` records should be accepted into future public pulls.
